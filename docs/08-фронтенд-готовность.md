# 08 · Готовность к разработке фронтенда (React/Next.js + Telegram Mini App)

Ответ на вопрос «насколько репозиторий готов к старту фронтенда». Коротко:
**UI-слой готов к спринту 0 сегодня**, контракты данных — нет (их в дизайн-системе
и не должно быть); ниже — что брать как есть, чего не хватает и план первой недели.

## 1. Вердикт по слоям

| Слой | Готовность | Что берёт фронтенд |
|---|---|---|
| Токены | ✅ 100 % | `tokens/tokens.css` (переменные) + `tokens/tailwind.config.preset.js` (подключается одной строкой) |
| Типографика/сетка | ✅ 100 % | fontSize-пресет (display…mono), брейкпоинты tablet 768 / desktop 1440 |
| Компоненты | 🟡 как спецификация | Все 106 имеют имя/вариант/состояния и визуал в спеках → верстка без вопросов «как выглядит»; кода пока нет (осознанно) |
| Экраны и маршруты | ✅ | Мапа E-XX → маршруты (раздел 3) + состояния |
| Потоки (UX) | ✅ | 6 потоков: кликабельный `prototype.html` + Present в Penpot |
| Контент | 🟡 | Лимиты символов заданы (`docs/05`); реальные тексты — задача методиста |
| API/данные | ❌ не входило в ТЗ | Набросок сущностей и эндпоинтов — раздел 4 (стартовая точка для бэкенда) |
| TMA-специфика | 🟡 | Safe areas, тема, MainButton — спроектированы; интеграционный код — раздел 5 |

## 2. Рекомендуемый стек

- **Next.js 14+ (App Router)** — веб-кабинеты (психолог/студент/супервизор/админ);
- **Tailwind + пресет репозитория**; headless-поведение — Radix (диалоги, тултипы, табы);
- **Графики**: recharts (радар — custom shape, линия — по данным 12 недель);
- **TMA**: `@telegram-apps/sdk` (initData, MainButton, BackButton, haptics, theme);
- **Формы**: react-hook-form + zod (схемы валидации из лимитов `docs/05`).

## 4. Сущности и API-стаб (стартовая точка для бэкенда)

Сущности читаются прямо из доменных компонентов:

- **User** (роль: psychologist/student/supervisor/client/admin; verification status; telegram_id?)
- **Scenario** (title, description, clientRole, difficulty 1–5, focusSkills[≤3 из 8], durationMin, status)
- **ScenarioGraph** (nodes: text/choice/scale/timer/input/card; edges — ветвления) — см. P1 в `docs/07`
- **Session** (scenarioId, userId, transcript[], emotionPoints[{t, value 0–10}], skillScores{8}, score, criticalEpisode?)
- **Game** (type: exercise/meditation/diary/technique, theme, steps[]: 7 типов из ТЗ 12.4)
- **ClientAccess** (code `A7X9-Q2`, deeplink, label-псевдоним, expiresAt, entriesLimit/used, status: active/expired/completed/revoked)
- **GameRun** (accessId, progress step/total, answers, anxietyBefore/After?)
- **SupervisionComment** (sessionId, timecode, author, template?, visibility: student-only)
- **AuditEntry** (actor, action, target, at) — append-only, 3 года
- **ClientNote** (E2E: ciphertext на сервере)

Эндпоинты (набросок): `POST /auth/telegram` · `GET /scenarios` · `POST /sessions/{id}/answer` ·
`POST /access` · `GET /g/{token}` (публичный) · `POST /g/{token}/answers` · `GET /me/progress` ·
`GET /admin/audit?from&to` · `POST /verification/{id}/decision`.

## 5. TMA-интеграция (чек-лист первой итерации mini app)

1. `initData` → валидация HMAC на бэкенде (никаких доверий клиенту).
2. Safe areas: отступы `safe-t` (56px) сверху и `safe-b` (80px) снизу — уже в пресете.
3. MainButton: enable/disable по валидности шага (макет состояния — E-53b), текст из шага.
4. theme_params → маппинг на color/dark/* ; форс-тёмная тема по ТЗ 11.1 как дефолт.
5. BackButton — на всех экранах кроме онбординга; haptics на выбор ответа.
6. Offline: баннер «нет соединения, прогресс сохранён локально» (см. P1 `docs/07`).
7. Диплинк `t.me/<bot>/app?startapp=<token>` → `GET /g/{token}`.

## 7. Риски

- Контент сценариев (методист) — блокирует наполнение, не блокирует каркас;
- E2E для заметок — требует бэкенд-решения раньше, чем экран E-32 пойдёт в код;
- Ветвления диалогов — до схемы из `docs/07` сценарии ограничены линейными.
