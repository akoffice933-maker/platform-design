# 09 · Схема сценария симулятора (контракт для методиста и бэкенда)

Закрывает P1-пункт №1 из [плана доработок](07-план-доработки.md): ветвления диалога
из «комментариев» превращены в машиночитаемый контракт. Один файл сценария
понимают методист, бэкенд и редактор (когда дойдёт до него).

## Файлы

| Файл | Что это |
|---|---|
| [`schemas/scenario.schema.json`](../schemas/scenario.schema.json) | JSON Schema **draft 2020-12** — формальный контракт |
| [`scenarios/exam-anxiety.json`](../scenarios/exam-anxiety.json) | Эталонный пример «Тревога перед экзаменом»: 16 узлов, 2 ветвления, критический эпизод |
| `tools/validate_scenario.py` | CLI-валидатор: schema + графовый линтер |
| `scenarios/exam-anxiety.graph.svg` | Визуальный граф примера (генерируется из JSON) |

## Быстрый старт

```bash
python3 tools/validate_scenario.py scenarios/*.json   # 0 = валиден
python3 tools/gen_scenario_graph.py scenarios/exam-anxiety.json   # перерисовать граф
```

CI-сниппет (в репозитории контента):

```yaml
- run: pip install jsonschema && python3 tools/validate_scenario.py scenarios/*.json
```

## Узлы (9 типов → экраны UI)

| Тип | Назначение | В UI | Ключевые поля |
|---|---|---|---|
| `card` | Брифинг о клиенте | E-21 (карточка сценария) | `title ≤48`, `body ≤200` |
| `text` | Реплика клиента | E-22 пузырь слева | `clientLine ≤90`, `emotionAfter` |
| `choice` | Выбор ответа психолога | E-22 варианты | `options[2..5]`: `text ≤64`, `scores`, `feedback`, `emotionAfter`, **`next` — у каждого свой (это ветвление №1)** |
| `scale` | Самооценка клиента 0–10 | паттерн E-42/scale | `prompt ≤60`, `selfRate` |
| `timer` | Пауза/заземление | E-24, паттерн E-42/timer | `seconds 1..300` |
| `input` | Свободный ответ | E-23 | `hints ≤3`, `maxLen ≤500`, `scores` на узле |
| `critical` | Острое состояние | **E-85**: пауза, рекомендации, эскалация | `risk`, `recommendations[2..4]`, `options` |
| `branch` | Условное ветвление | невидимый узел (ТЗ 12.4) | `when: {emotionAtLeast \| optionSelected \| skillTotalAtLeast}` → `then`, `else` |
| `end` | Финал → данные для разбора | E-25 | `outcome: {summary ≤200, debrief ≤160, completed}` |

## Два паттерна ветвления

1. **Через вариант ответа** — у каждого `option` свой `next`. Пример из эталона:
   `c1.reflect → g1` (контакт), `c1.advice → a1` (совет без исследования — эмоция растёт).
2. **По состоянию** — узел `branch`. Первое истинное условие выигрывает:
   `br1: если эмоция ≥ 7 → crit1, иначе → q1`. Условия комбинируются:
   `optionSelected: "crit1.push"`, `skillTotalAtLeast`.

## Оценка и эмоции

- **`scores`** — целые −3…+3 по 8 навыкам (`listening, empathy, boundaries,
  structuring, emotion_work, resistance, questioning, reflection` — ID совпадают
  с токенами `color/skill/*`). Сессионный балл считает бэкенд: Σ очков,
  нормировка и веса фокус-навыков — его решение, схема фиксирует сырые дельты.
- **`feedback.strength / growth`** — попадают в E-25 («сработало / улучшить»).
- **`emotionAfter` (0–10 + подпись)** — линия эмоций: E-22 индикаторы, зоны цветов
  `color/emotion/low|mid|high` (0–3 / 4–6 / 7–10), динамика в E-25; `scale.selfRate`
  даёт пункты «до/после» (7 → 4 в Э-54/D-09).

## Правила графа (проверяет валидатор)

- все `next / then / else` указывают на существующие узлы; `optionSelected` —
  на существующий вариант (`"<nodeId>.<optionId>"`);
- все узлы достижимы от `graph.start`; достижим хотя бы один `end`;
- в каждом `choice`/`critical`: уникальные `id` вариантов, ≥1 вариант
  с положительной суммой очков; в `critical` рекомендуется вариант,
  ведущий к прерванной сессии (инструкторский разбор);
- `focusSkills` должны где-то оцениваться.

**Негативный тест** пройден: обрыв ссылки, удаление «хорошего» варианта и битая
ссылка условия — по 4 ошибки, код выхода 1.

## Методисту

1. Скопировать `scenarios/exam-anxiety.json` как шаблон (там все 9 типов узлов).
2. Лимиты символов — как в макетах ([docs/05](05-методисту-тексты.md)); schema их и enforce'ит.
3. Перед сдачей: `python3 tools/validate_scenario.py <файл>` — должен отвечать ✓.
4. Граф для презентации методики: `python3 tools/gen_scenario_graph.py <файл>`.

## Бэкенду

- Хранить как документ; `schemaVersion: "1.0"` проверять при импорте
  (минорные версии — только добавление полей, ломающие изменения — новая мажорная);
- Runtime-обход графа: `choice/critical` → ждём `optionId`; `input` → свободный текст
  (скоринг близости к `hints` — на стороне бэкенда/LLM); `branch` → вычислить условия
  из текущего состояния (эмоция последнего узла, выбранные варианты, Σ очков);
- Прогресс клиента (E-30…E-44) хранит `nodeId` — возобновление с середины бесплатно.
